# TruckFood — MVP Definition

**Version:** 1.0.0  
**Status:** Discovery baseline — subject to validation

## MVP Objective

Prove that TruckFood can provide professional drivers with useful, trustworthy information around a journey without trying to build a complete truck navigation system on day one.

## MVP Must Deliver

### 1. Driver

- account;
- basic profile;
- basic vehicle profile.

### 2. Map & Search

- map-based discovery;
- location search;
- category filters;
- location details.

### 3. Parking

- truck-relevant parking locations;
- practical parking information where known;
- source/freshness indicators.

### 4. Food

- restaurant discovery;
- truck access/parking information where available;
- opening hours where available;
- community feedback.

### 5. Community

- reviews;
- useful observations;
- photos;
- reports/corrections;
- basic moderation.

### 6. Trust

- provenance;
- freshness;
- basic confidence state;
- clear uncertainty communication.

## MVP Should Prepare For

- vehicle-aware restrictions;
- route-context analysis;
- stop planning;
- stronger trust scoring;
- international expansion.

## Explicitly Out of MVP

The following should not be allowed to silently enter the first release:

- fully autonomous truck routing;
- guaranteed legal/safety routing;
- fleet management suite;
- complex monetisation infrastructure;
- broad social-network features;
- unnecessary gamification;
- excessive real-time features without reliable data sources.

## MVP Success Criteria

The MVP should be considered successful only if real professional drivers can repeatedly use it to answer practical questions such as:

- where can I stop;
- where can I park my truck;
- where can I eat;
- what do other drivers report;
- how trustworthy is this information.

Quantitative targets will be defined after discovery and user validation.
