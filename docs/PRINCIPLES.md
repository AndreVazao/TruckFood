# TruckFood — Engineering & Product Principles

**Version:** 1.0.0  
**Status:** Active

## Product

1. Drivers first.
2. Safety and practical usefulness before vanity features.
3. A journey is more important than a single destination.
4. Restaurants are one part of a broader professional-driver ecosystem.
5. Trust must be earned through provenance, freshness and community validation.

## Data

6. Never hide uncertainty.
7. Every critical fact should have an identifiable source where possible.
8. Time-sensitive information must carry freshness semantics.
9. Official, provider, community and inferred information must be distinguishable.
10. Data quality is a product feature.

## Engineering

11. Stability before feature volume.
12. Architecture before implementation.
13. API and domain contracts before client coupling.
14. Test critical behaviour before scaling it.
15. Prefer reversible decisions while uncertainty is high.
16. Avoid unnecessary vendor lock-in.
17. Avoid destructive automation.
18. Keep the system observable and diagnosable.

## Project Management

19. Documentation is part of the deliverable.
20. Important decisions become ADRs.
21. Large proposed changes become RFCs before architecture changes.
22. Every major phase closes with a state update.
23. The repository remains the source of truth.
24. Do not silently replace previous decisions; record changes and reasons.
